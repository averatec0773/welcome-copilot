A working answer to Mentella Health’s application task

Welcome Copilot

HR tracks hiring in a shared Google Sheet. When a row turns “Hired”, this system sends the welcome email, keeps proof of every send, and alerts a human the moment anything stops working. It is running live right now.

Live demo: https://welcome-copilot.vercel.app

Source: https://github.com/averatec0773/welcome-copilot

An unofficial demo built by one applicant. All people and policies are fictional, and every recipient address is a + alias of the author’s own inbox. Every screenshot in this document is taken from the live system, unedited except for cropping.

The task

The question, and the shape of the answer

“Sketch how you would automate the welcome email (tracked in a shared spreadsheet several people edit): what you’d use, what could go wrong, and how you’d know if it silently stopped working.”

Instead of a one-page sketch, this is a working system. The written sketch still exists (docs/sketch.md in the repo), but every claim in it can be checked against a live deployment.

What it uses

Google Apps Script bound to the team’s existing shared Sheet, on a 5-minute trigger. No new tool for HR to learn: the spreadsheet stays the source of truth, and the automation works around how the team already works. A small Next.js console on Vercel gives everyone a read-only window into the pipeline, plus a Claude-backed assistant that answers new-hire questions from the onboarding handbook.

What could go wrong, by design

  • A typo’d email address → the row is marked INVALID before any email leaves.
  • The same person pasted twice → the second row is marked DUPLICATE; only the first may ever send.
  • A re-sorted sheet mid-run → every write is keyed by hire ID, not row position, so results land on the right person.
  • A crash between “sending” and “sent” → a SENDING marker stays visible for a human to review; it is never auto-retried into a double send.
  • Gmail’s daily quota running out → the pipeline holds sends and says so, rather than failing quietly.

How you’d know it silently stopped

Three independent alarms: instant error emails to the operator, a dead-man’s switch (healthchecks.io) that alerts on silence rather than on errors, and a daily digest with the bottom line. The failures that cannot report themselves are exactly what the dead-man’s switch exists for.

Reliability

Why it never sends twice, and never fails quietly

The invariants

  • Idempotent by record, not by memory. The sheet itself records every send. A row with a welcome_sent_at timestamp will never send again, whatever else happens.
  • At-most-once sending. A SENDING marker is written and flushed before Gmail is called. If the script dies mid-send, the marker stays for a human; it is never auto-retried.
  • Writes keyed by hire ID. Every write-back verifies the row still holds the same hire ID, so a re-sorted sheet cannot misdirect a result.
  • Fail closed. Anything other than an explicit dry_run = FALSE means rehearsal mode: drafts, not sends.

The three alarms

AlarmCatchesLatency
Instant alert emailsErrors the pipeline can see and reportImmediate
Dead-man’s switchSilence: a disabled trigger, revoked auth, a dead scriptMinutes
Daily digestThe slow drift a human should read aboutDaily, 8:00

The digest’s closing line: “No news from me tomorrow would itself be a signal. Check the triggers.”

Limits, all of them visible

Every rate limit in the demo shows the visitor a live remaining count before they hit it: simulations per visitor and demo-wide, assistant questions per minute and per day. A limit someone discovers by silently failing is treated as a bug.

What’s next

Where this would go inside Mentella

  • First: point the same pipeline at the real hiring tracker behind a dry-run flag, and let it draft (not send) for a week while the team reads the Outbox.
  • Then: extend the pattern to the other spreadsheet-tracked handoffs around onboarding: credentialing checklists, IT provisioning, first-week reminders.
  • Where systems have no API (several core clinical and billing systems don’t): treat the scheduled manual export as the interface, validate it loudly, and report on it. A working slice of that approach ships in this demo’s repo.
  • The assistant grows with the handbook. It only ever answers from documents the team controls, with citations, so growing it is writing docs, not training a model.

Try it yourself

Open https://welcome-copilot.vercel.app, click through the console, and ask the assistant one of the suggested questions. With the access code, press ▶ Simulate a hire and watch a real email go out in about thirty seconds.
